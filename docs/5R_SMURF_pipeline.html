5R / SMURF 流程解析

5 对引物在一次多重 PCR 中扩增 16S rRNA 的 5 个短区域，SMURF 再把五个区域的 reads 放进同一个似然模型联合求解，得到接近全长 16S 的物种分辨率。本页按代码执行顺序拆解每一步，并给出引物、算法与数据库三方面的改进建议。

1,402,801参考序列（GreenGenes 13_5）
2 × 126 nt示例数据读长（kmer_len）
328 / 328Python 复现与官方结果一致的物种

方法出处：Fuks G. et al. Combining 16S rRNA gene variable regions enables high-resolution microbial community profiling. Microbiome 6:17 (2018)。仓库为 MATLAB 实现（mFiles/，约 1,000 行），另附 Linux 编译版和 GreenGenes 预建 k-mer 库（GG_5R/，约 120 MB）。

5 个扩增区域在 16S 上的位置

坐标为 E. coli 16S 编号（近似值）。扩增子长度由数据库中的 match_pos_fwd / match_pos_rvs 估算。所有扩增子都短于 2 × 126 = 252 nt，所以双端 reads 在每个区域都有重叠，R4 重叠最多（约 90 nt）。

流程总览

入口为 main_5R(illumina_files_dir, db_dir, db_name, results_filename, kmer_len, generate_group_results)。对每个样本目录调用 main_multiple_regions，最后把所有样本汇总成一张物种丰度表。括号中的数字取自示例样本 RDB1_TTGGTGCA。

  1. 配置与载入数据库

    get_configs.m · main_5R.m

    设定引物、质量阈值、错误率等参数；载入参考序列编号 Header_uni 与七级分类 taxonomy_db.mat。

    kmer_len = 126pe = 0.005nMM_cut = 2tol = 5e-7

  2. 拆分样本目录

    split_files2directories.m · extract_sample_name.m

    若所有 FASTQ 混在同一目录，按文件名中 _L00x 之前的部分建子目录；自动解压 .zip/.gz。

  3. 质量过滤与去重

    read_fastq_save_unireads.m

    两端均截取前 126 nt；不含 N；Q>30 的碱基 ≥ 75% 且 Q<10 的碱基 < 3 个。合格的 read 对拼成 [R1 | R2] 后完全去重计数。

    299,346 对→ 286,199 合格（95.6%）

  4. 按引物分配区域

    read_unireads_save_split_to_regions.m · unambiguit_one_seq.m

    R2 反向互补后，开头匹配正向引物、末尾匹配反向引物的反向互补（各 ≤ 2 错配）即归入该区域，随后切除引物。

    R1 33,189R2 134,783R3 10,763R4 37,922R5 63,85298% reads 被分配

  5. 载入区域 k-mer 库

    load_bact_DB.m

    把预存的 160+160 nt k-mer 截成与 read 同形（去引物、每端 126 nt）并去重，得到“参考序列 → 本区域 k-mer”的映射。

  6. 构建似然矩阵 A

    build_A_matrices.m

    丢弃计数 < max(1e-4 × 区域总数, 2) 的 read；对剩余每条 read 计算与全部 k-mer 的 Hamming 距离，≤ 2 者给出似然。

    每区域 258–391 条唯一 readA 非零元约 970 万

  7. 过滤、合并、EM 求解

    solve_iterative_noisy.m · ml_em_iterative.m

    排除缺少完全匹配 read 的候选；列相同的参考序列合并为 group；删除“被包含”的 group；EM 求最大似然丰度，再除以可扩增区域数。

    117,430 条候选序列→ 10,189 个 group→ 1,345 个进入 EM→ 404 个非零 group

  8. 分配 reads、注释、汇总

    reconstruction_func.m · save_reconstruction_new_nogroups.m · scott_format_newer_func.m · build_scott_list_new.m

    按后验概率把 read 计数分给 group；每个 group 取占比最高的物种名（硬决策）；跨样本合并输出 SPECIES_*.txt 与 ReadCountStats_*.txt。

    286 个物种（RDB1）67 个物种（RDB123）

Reads 处理细节

拼接后的 read 结构

由于扩增子比 252 nt 短，两段之间其实有重叠。代码没有合并双端，而是直接拼接。数据库按同样方式构造，所以模型内部自洽；代价是重叠区的测序错误被计算两次，也错过了用重叠区相互校正的机会。

引物匹配规则

对每个区域，正向引物的所有简并展开版本与序列开头逐位比较（read 中的 N 不计为错配），取最小错配数；反向引物同理比较序列末尾。两端都 ≤ 2 时归入该区域。一个 read 理论上可同时归入多个区域，但示例中没有出现。

k-mer 数据库

每个区域一个 .mat 文件，包含以下字段（以 R1 为例）：

变量形状含义
values273,135 × 320每个唯一扩增子的前 160 nt 与后 160 nt，含引物，正链方向
indInValue1,402,801 × 1参考序列 → values 行号；0 表示引物错配 > 2，不扩增
is_perfect_match1,402,801 × 1两端引物都 0 错配，用于候选过滤
match_pos_*, Header_amp, Dictionary构建时的辅助信息，流程中未使用（Dictionary 读入最慢）

截短到 126 nt 后，R1–R5 分别剩约 26 万、20 万、29 万、15 万、20 万个唯一 k-mer。平均每个 k-mer 被 4–7 条参考序列共享，这是单区域分辨率有限的根源，也是联合五个区域的意义所在。

仓库没有附带构建这些文件的脚本。原始 GreenGenes 序列文件 …_16S.mat 也未随仓库提供，因此 generate_group_results = 1 在默认配置下会因找不到序列文件而报错。

似然模型

记区域 r 中唯一 read 为 y，参考序列为 j，d 为 read 与 j 在该区域 k-mer 的 Hamming 距离，L 为去引物后的长度：

Ar[y, j] = Pr(y | j) = (1 − pe)L−d · (pe/3)d　　当 d ≤ 2；否则为 0　　（pe = 0.005）

五个区域的 A 纵向拼成一个矩阵。观测向量 yy 为 read 计数除以所有区域的总计数。每列再除以该参考序列可被扩增的区域数 nj，使列和约为 1。于是第 j 列描述“如果所有 reads 都来自 j，它们应如何分布在五个区域的各条 read 上”。

d=1 的似然约为 d=0 的 1/600，d=2 约为 1/360,000，所以错配在这里起的是“软惩罚”作用：一条 read 若与某参考序列完全匹配，几乎不会再被分给只差 1 个碱基的其他序列。

求解与分组

① 候选过滤

若 j 在区域 r 的两个引物都 0 错配（理论上一定会扩增），则区域 r 必须至少有一条与 j 完全匹配的 read，否则排除 j。j 还必须至少匹配到一条 read。

② 合并不可区分者

A 中列完全相同的参考序列在这五个区域上无法区分，合并为一个 group，这是输出的最小单位。RDB1 共 10,189 个 group。

③ 删除被包含者

若 group i 的非零 read 集合是 group j 的真子集，删除 i。这是一种简约性启发式。RDB1 中删去 8,844 个（87%），RDB123 删去 1,577 / 1,831。

④ EM 迭代

θ = A·x；xj ← xj · Σy Ayj · yy/θy。初值 x ∝ Aᵀy。当 Σ|1 − factorj|·xj < 5×10⁻⁷ 时停止，示例约迭代 3,000 次。

⑤ 换算丰度

xj 是 reads 份额。可扩增区域多的细菌贡献的 reads 更多，所以最终丰度为 xj/nj 归一化。这里未做 16S 拷贝数校正。

⑥ 分配 reads

按后验 Pr(j | y) ∝ Ayj·xj 把每条 read 的计数分给各 group，四舍五入后汇总为 assigned_reads。

注释与输出

一个 group 往往包含数十到上千条参考序列，各自的分类可能不同。save_reconstruction_new_nogroups.m 在 domain 到 species 的每一级统计 group 内各分类所占比例。scott_format_newer_func.m 随后做硬决策：在 species 级，整个 group 的丰度全部记给占比最高的物种名（并列时取字典序最前者），名称中的 Assigned 改为 Unknown。

GreenGenes 13_5 中 50% 的序列物种名是占位符（Assigned speciesN），19% 的属名是占位符，所以输出里大量出现 Unknown species12 这类条目。它们代表“该属内某个未命名的序列簇”，不同数据库之间不能直接对应。

Python 复现结果

python_5R/smurf5r.py 按函数对应 MATLAB 代码，notebooks/5R_SMURF_step_by_step.ipynb 逐步运行并展示每一步的中间结果。最耗时的 read 与 k-mer 比对改用鸽巢原理：把序列切成 3 段，距离 ≤ 2 的两条序列至少有一段完全相同，先用 3 张哈希表找候选再精确计算距离。Notebook 中验证了它与暴力比对给出完全相同的结果。每个样本运行约 10 秒（不含载入数据库）。

高补上古菌与 Bacteroidetes 的缺口

  • 古菌两个门平均可扩增区域数 < 0.02，也就是完全检测不到。若研究涉及肠道产甲烷菌（如 Methanobrevibacter），需要加一对古菌或通用原核引物。
  • Bacteroidetes 在 R1 上 0 错配比例为 0，R4 只有 12% 可扩增，R3 0 错配仅 1%。R1 正向引物和 R4 正向引物应针对该门重新设计简并位点。
  • Planctomycetes 的 R1、R2、R5 覆盖低于 45%；Actinobacteria 的 R4 为 55%。

高用新数据库重新评估并迭代引物

  • 在 SILVA 138.2 或 GTDB 上做 in-silico PCR（SILVA TestPrime、ecoPCR，或本仓库新增的 build_region_db_from_fasta），按门、属统计覆盖度。
  • 统计每个引物位点的错配位置分布。3′ 端最后 3–5 个碱基的错配对扩增效率影响最大，应优先在这些位置加简并。
  • 每轮修改后同时检查引物二聚体、Tm 一致性和多重体系中的交叉扩增。

中考虑增加或替换区域

  • 当前未覆盖 V1、V4、V7、V9。V1 对 Staphylococcus、Cutibacterium、Streptococcus 等皮肤和口腔菌的种水平区分有帮助。
  • V4（515F/806R）是 EMP 等大型项目的标准区域，加入后便于和公开数据比对。
  • 模型本身支持任意数量的区域，增加区域的主要成本在多重 PCR 的优化上。代码中 nR = 5 的硬编码需要先改掉。

中用实验校正区域扩增偏倚

  • 模型假设五个区域扩增效率相同，但示例中 R2 获得的 reads 是 R3 的 6–12 倍。
  • 建议用 ZymoBIOMICS 等已知组成的 mock community 估计每个区域、每类错配的扩增效率，再作为权重写进 A 矩阵。
  • 每批实验带阴性对照（试剂空白、石蜡空白），FFPE 和低生物量样本尤其需要。

改进建议：算法

高改用基于质量值的误差模型

现在所有位置使用同一个 pe = 0.005，且只允许替换。可改为按每个碱基的 Phred 质量计算似然（DADA2 和 Deblur 的做法），并允许 1–2 nt 的插入缺失，从而把目前因 indel 被丢弃的 reads 找回来（示例中每区域有 17–3,285 条 reads 未匹配）。

高先合并双端，再在扩增子水平去噪

所有扩增子都短于 252 nt，可以先用 VSEARCH / PEAR / DADA2 合并双端，在重叠区相互校正。再对每个区域生成 ASV，用 ASV 代替原始唯一 read 进入 SMURF。这样能把 1e-4 的低丰度阈值降下来，提高稀有菌的检出。

中读长不是越长越好

Notebook §10.2 中把 kmer_len 从 100 提到 126，合格 reads 略减，最终 group 数和 group 大小也没有改善，因为多出的碱基主要落在两端重叠区。kmer_len=100 时 EM 在 10,000 次迭代内未收敛。对 5R 扩增子，与其追求更长读长，不如合并双端、按区域设定截取长度，并把最大迭代次数和收敛情况写进日志。

中按测序深度设定检出下限

稀释实验（§10.3）显示：约 3 万条 reads 可找回 90% 的丰度 ≥0.1% 的物种，1.4 万条时降到 87%，5,700 条时只剩 60%。建议样本至少 3 万条合格 reads，并在报告中标注每个样本的可靠检出下限。

中重新审视“删除被包含者”

真子集规则在 RDB1 中删掉了 87% 的 group（10,189 → 1,345），删除只依据非零模式，不看似然值。一个真实存在、但某区域没有扩增的细菌可能因此被删掉。建议改为模型选择（比较删除前后的似然或 BIC），或在 EM 中加入稀疏先验，例如 Dirichlet 先验或 L0/L1 惩罚。

中给出不确定性

EM 只给点估计。可以对 reads 做 bootstrap，或从后验做 MCMC 抽样，给每个 group 的丰度报告置信区间。同时输出 group 大小和多数物种所占比例，提示哪些物种名并不确定。

中改进分类赋值方式

硬决策会把整个 group 的丰度记给占比最高的物种，即使它只占 30%。可改为 LCA（共同祖先）赋值，只在多数比例超过阈值（如 80%）时给出种名；或者保留按比例拆分的结果，作为第二张表输出。

低工程与性能

  • 用鸽巢索引或 Bowtie2 代替暴力比对；删除未使用的 debug_dist_mat；被包含判断改用稀疏运算。
  • EM 加 SQUAREM 加速，去掉依赖时间的剪枝，固定随机种子。
  • 输出 BIOM / QIIME 2 兼容格式，加 16S 拷贝数校正（rrnDB）。
  • 提供 Python / Nextflow 版本，摆脱 MATLAB 许可与 R2019b 运行时依赖。

改进建议：数据库

当前使用的 GreenGenes 13_5 发布于 2013 年，之后没有再更新。其中 50% 的物种名是占位符，属和种的命名也与现行分类体系有较大出入。

数据库特点适用场景
SILVA 138.x SSU Ref NR99维护活跃、质量筛选严格，覆盖细菌、古菌和真核生物；物种级注释较弱默认首选，用于引物评估和通用研究
GTDB（16S 由基因组提取）以基因组系统发育为准的统一分类，种级标签更一致；只收录有基因组的类群需要种级名称、要与宏基因组结果对接时
Greengenes2（2022 起）把 16S 与全基因组整合到同一棵树，兼容 QIIME 2 生态延续 GreenGenes 体系、与其他扩增子数据合并分析
NCBI RefSeq 16S 靶向位点以模式菌株为主，物种名可靠但序列数少作为种名校验的辅助库
专用库：eHOMD（口腔、呼吸道）等针对特定生境精细整理研究对象明确时作为补充

高补齐建库流程

仓库缺少从 FASTA 生成 values / indInValue / is_perfect_match 的脚本，这是更换数据库的主要障碍。新增的 build_region_db_from_fasta 用同样的规则（引物 ≤ 2 错配、取前后各 160 nt）生成相同结构，可以直接接入现有流程。

中按研究场景裁剪数据库

140 万条序列中有大量环境类群。针对人体样本，可以只保留宿主相关类群，或先用全库运行一次、再在检出的属内细化。候选更少时 group 更小，EM 也更稳定。对 FFPE 肿瘤样本，还应建一份常见污染菌清单（如 Ralstonia、Bradyrhizobium、Afipia）。

低记录数据库版本

把数据库名称、版本、引物版本、构建参数写入每份结果文件的表头，并给 k-mer 库计算校验和，保证结果可追溯。
